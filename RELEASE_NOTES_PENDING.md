# Release notes pending

## Behaviour changes

- **An update now retires the old pipe on every Open WebUI worker** - With several workers, updating the pipe (from the Update tab, by the automatic update, or by saving it in Workspace → Functions) replaced it at once only on the worker that made the change. Every other worker kept running the old version, with its background jobs, until a chat or a model list next reached that worker, which on a quiet worker could take hours. The pipe now tells every worker over Open WebUI's Redis, and each worker retires its old copy as soon as no chat is using it; Open WebUI loads the new version there on the next request. Deleting the pipe stops it on every worker the same way. This needs Redis, as Open WebUI's own multi-worker setup does, and starts working with the first update made after this version is installed, because the copies being replaced must already listen for it.
- **Tool results are processed by Open WebUI again on Open WebUI 0.13.4** - Open WebUI 0.13.4 removed browser-run tool servers and with them a setting of the function that prepares a tool's result for the model. The pipe still passed that setting, so in Pipeline mode every tool result skipped that preparation: the model got the raw result as plain text, an image a tool returned arrived as a long `data:` line instead of an image, and embedded panels and tool-server replies were not unpacked. The pipe now passes the setting only to Open WebUI releases that still take it.
- **The Pipe Dashboard connects again on Open WebUI 0.13.4** - Open WebUI 0.13.4 removed the relay between its workers that the dashboard panel used for its sign-up and its tab clicks, so a panel opened there never connected and its tabs did not load. The panel now sends them as requests to the dashboard model through Open WebUI's own chat endpoint, which every worker accepts on every Open WebUI release the pipe supports; a worker that has not run the pipe yet loads it on the spot. These requests are answered ahead of the pipe's chat limits, so the dashboard keeps working for a user whose chats are refused after repeated errors, or while the request queue is full. Dashboard panels saved in chats by earlier releases keep their old way of sending: open the dashboard again with the `dashboard` command.
- **The Pipe Dashboard's live view no longer stops at the Storage tab** - Since 2.9.1 a name clash in the panel made every live update fail at the Storage figures, on every Open WebUI release, so the Storage tab stayed empty and the configuration, worker and plugin figures shown after it were not refreshed. Open the dashboard again with the `dashboard` command to get the corrected panel.
- **A message sent while a reply runs its tools is answered straight away in Pipeline mode** - On Open WebUI 0.13.4 a message typed while a reply is still running waits on the server. Open WebUI's own tool loop then stops after the tool step it is on and answers the new message next; in Pipeline mode the pipe kept running every remaining tool step first. The pipe now asks Open WebUI after each tool step and stops there in the same way, so the new message is answered next with what the reply had done. On earlier Open WebUI releases the pipe does not ask, and nothing changes.
- **Workers take turns when they check the model entries** - With several Open WebUI workers, an update loaded the new pipe on every worker at about the same moment, and each one at once checked and rewrote every Open WebUI model entry the pipe makes. Together they ran the database out of connections ("too many clients"), misread entries that existed as missing and tried to insert them again, and could make a model list fail. The workers now take turns under Open WebUI's own cross-worker lock, as Open WebUI does for its own one-worker jobs, so after an update the checks finish one after another within a couple of minutes. This needs Redis, as Open WebUI's multi-worker setup does; a single worker is unchanged.
