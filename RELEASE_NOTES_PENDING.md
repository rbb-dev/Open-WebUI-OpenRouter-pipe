# Release notes pending

- **The Pipe Dashboard panel's requests need the Authorization header again** - Since 2.9.2 the panel's sign-up and tab clicks reach the dashboard through Open WebUI's chat route, which also accepts the login cookie. A request that held only the cookie and named the user's own live dashboard socket was answered there, where the dashboard's own route always required the `Authorization` header. With Open WebUI's default cookie setting (`SameSite=lax`) a browser does not send that cookie with a request from another site, but an install that set it to `none` could have been reached that way. The dashboard now refuses a panel request without the header, as its own route does; the panel always sends it. A panel request is also read only within the route's own size and nesting limits.
