# Release notes pending

## Behaviour changes

- **Streamed replies to programs with no chat are built by Open WebUI's own chunk helper again on Open WebUI 0.13.0** - Open WebUI 0.13.0 renamed the helper (`openai_chat_chunk_message_template` is now `chat_completion_chunk_template`), so the pipe fell back to its own copy, whose chunk ids look different and carry no `logprobs` key. The pipe now uses the new name, the old one on Open WebUI 0.12, and its own copy only when neither exists.
- **On Open WebUI 0.13.0 an automatic update of the pipe is announced to event functions and webhooks again** - Open WebUI 0.13.0 publishes an event only for a request, and the dashboard's automatic update runs without one, so its `function.updated` event was dropped and the failure was logged only at debug level. The update now hands Open WebUI a request built around its app, the way Open WebUI announces its own start-up, and an announcement Open WebUI does not take is logged as a warning, once.
- **Open WebUI 0.13's "Auto" tool permission mode now works with the pipe** - Under Auto, Open WebUI reviews each tool call and asks the user when its review says a call needs approval. The pipe handed a turn to Open WebUI only under "Ask" and ran every call itself under "Auto", so no call was reviewed. Auto is now treated like Ask: on a streamed reply in a saved or temporary chat Open WebUI runs and reviews the calls, and where a turn cannot be handed to Open WebUI, Open WebUI's tools are not offered.
- **Tools run again with Open WebUI 0.13's Tool Call Labels on** - With Tool Call Labels on, Open WebUI adds a short label field to every tool's parameters for the model to fill, and removes it again before a tool runs. In the pipe's Pipeline mode the field reached the tool, which refused it, so every tool call failed. The pipe now removes it before the tool runs, as Open WebUI does, and its tool cards show the labels. The same applies to the review field Open WebUI's Auto tool permissions add.
