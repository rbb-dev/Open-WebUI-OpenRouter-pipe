# filters/

This folder contains reference Open WebUI filter functions used alongside the OpenRouter pipe.

Every `.py` file in this folder is GENERATED, not hand-written. Each one is the output of a `FilterManager` renderer, and `scripts/build_reference_filters.py` regenerates all of them:

```bash
python scripts/build_reference_filters.py
```

It writes only the files whose bytes actually differ, and prints what it changed. Run it after editing any renderer. `tests/test_web_tools_filter.py` is the net that fails CI when a copy and its renderer drift apart, so a drift you did not regenerate is caught even if you never remember to run the script.

## OpenRouter Web Tools

- `openrouter_web_tools.py` is the companion *toggleable filter* used to configure OpenRouter server tools (web search, web fetch, datetime) for the OpenRouter pipe.
- The pipe embeds a canonical copy of this filter and can **auto-install/auto-update** it into Open WebUI’s Functions DB when `AUTO_INSTALL_WEB_TOOLS_FILTER` is enabled.
- The copy in this repo is generated by `FilterManager.render_openrouter_web_tools_filter_source()` via `scripts/build_reference_filters.py`, and `tests/test_web_tools_filter.py` fails if the two diverge. Change the renderer, not this file.
- The filter is included here for review and manual installation, but **the live behavior is driven by the embedded copy inside the pipe** when auto-install is enabled.

If you edit `openrouter_web_tools.py` in this repo, it will not automatically update your running Open WebUI unless you paste/install it manually (or you update the embedded filter source in the pipe). A copy you switch off yourself in Open WebUI's Functions list stays off: the pipe keeps its code up to date but never switches it back on. One this version switched off itself comes back on its own when you enable the feature again. Turning an `AUTO_INSTALL_*` valve off retires the rows the pipe installed for it — switched off, not deleted, so their settings survive — and turning it back on brings them back; in that retirement pass a copy you installed by hand carries no such record and is left alone, and neither does a row installed by an earlier build: it carries no `openrouter_pipe:installed_by` record, so it is claimed on the first refresh on which its valve is on and retired only from that refresh on (stated once in `docs/openrouter_provider_routing.md`). The Video Generation rows are the exception, because their master switch does not retire them by install record: `ENABLE_VIDEO_GENERATION` identifies them by their source, so a copy you made by hand of one of these filters' source is switched off too, and comes back on when the valve does. A filter that was already off before this version stays off: switch it on in Workspace > Functions if you want it.

## OpenRouter Image Generation

- `openrouter_image_gen.py` is the companion *toggleable filter* for OpenRouter's image generation server tool.
- **This file is generated, not hand-written.** It is `FilterManager.render_openrouter_image_gen_filter_source(dedicated_image_api=True)` with no model and no contract, and `tests/test_web_tools_filter.py` fails if the two diverge. Edit the renderer in `open_webui_openrouter_pipe/filters/image_filter_renderer.py`, then run `python scripts/build_reference_filters.py`.
- The settings it offers come from the selected model's own published list of what it accepts. With no arguments the renderer has no such list to read, so the copy here shows the unread case: the six controls are all there, but each offers what OpenRouter's image API accepts in general instead of that model's own choices, and the `IMAGE_GENERATION_MODEL` valve's description says so. The pipe re-renders it for whichever model that valve names, and the installed copy narrows those controls to that model's own values.
- The pipe can **auto-install/auto-update** it into Open WebUI's Functions DB when `AUTO_INSTALL_IMAGE_GEN_FILTER` is enabled.
- The filter is included here for review and manual installation, but **the live behavior is driven by the embedded copy inside the pipe** when auto-install is enabled.

## Direct Uploads toggle

- `openrouter_direct_uploads_toggle.py` is the companion *toggleable filter* used to bypass Open WebUI RAG for chat uploads and forward them to OpenRouter as direct file/audio/video inputs.
- The pipe embeds a canonical copy of this filter and can **auto-install/auto-update** it into Open WebUI’s Functions DB when `AUTO_INSTALL_DIRECT_UPLOADS_FILTER` is enabled.
- The copy in this repo is generated by `FilterManager.render_direct_uploads_filter_source()` via `scripts/build_reference_filters.py`, and `tests/test_web_tools_filter.py` fails if the two diverge. Change the renderer, not this file. This pair is the one that drifted 24 lines apart under two-copy hand editing, with the copy that was NOT the one users get being the one that drifted.
- The filter is included here for review and manual installation, but **the live behavior is driven by the embedded copy inside the pipe** when auto-install is enabled.

If you edit `openrouter_direct_uploads_toggle.py` in this repo, it will not automatically update your running Open WebUI unless you paste/install it manually (or you update the embedded filter source in the pipe).
